# Архитектура платформы

## Границы продукта

На текущем этапе каталог содержит только товары и товарные магазины. Услуги и
заведения намеренно не входят в модель первого релиза. Основной сценарий:
покупатель находит товар поблизости, сравнивает предложения, сохраняет в
избранное и бронирует без онлайн-оплаты на 2 часа.

## Компоненты

- iOS покупателя обращается по HTTPS/JSON к Fastify API.
- Будущий отдельный клиент продавца использует тот же API с отдельными ролями.
- API хранит транзакционные данные в PostgreSQL/PostGIS.
- Структурированные логи и аудит вынесены из пользовательских ответов.
- Авторизация по телефону подключается через адаптер российского SMS-провайдера.

Компонент apps/customer-ios — SwiftUI, iOS 17+, async/await, MapKit, Keychain.
Компонент services/api — stateless API, валидация Zod, транзакции PostgreSQL.
PostgreSQL хранит каталог, геоданные, остатки и брони. Имя и телефон шифруются
на уровне приложения AES-256-GCM; для поиска телефона используется отдельный
HMAC. Приложение продавца будет отдельным клиентом и не встраивается в
приложение покупателя.

## Инварианты

1. stock не меньше reserved_stock, оба значения неотрицательны.
2. Создание и отмена брони блокируют строку предложения и меняют
   reserved_stock в одной транзакции.
3. Просроченные брони освобождаются идемпотентным фоновым процессом.
4. Цена брони фиксируется в unit_price_minor; последующее изменение цены
   карточки её не меняет.
5. Клиент не определяет права: все проверки пользователя и роли выполняет API.
6. Геопозиция используется для сортировки, но не сохраняется в профиле.

## Контуры

- local: Docker Compose, debug-заголовок с тестовым UUID.
- stage: отдельная БД без реальных ПДн, HTTPS, production-подобные настройки.
- production: только инфраструктура в РФ, секреты из KMS/Vault, debug-режим
  запрещён, резервные копии зашифрованы, доступ по least privilege.

## Масштабирование

API не хранит локальное состояние и масштабируется горизонтально. Поиск
начинается с PostgreSQL FTS; при росте каталога можно вынести индекс в
OpenSearch, сохранив PostgreSQL источником истины. Изображения должны храниться
в S3-совместимом объектном хранилище в РФ с закрытыми исходными бакетами и
короткоживущими signed URL.
